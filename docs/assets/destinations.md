# /images/destinations

Each destination card on `/destinations` looks for a photo at
`/images/destinations/<slug>.png` (see `src/data/destinationCatalogue.js`).

**If the file exists, it's shown, filling the card's image frame
(`object-fit: cover`, same aspect ratio on every card).**

**If it's ever missing or fails to load, the card falls back to a
plain neutral placeholder (a soft tint + a small pin icon) instead of
a blank or broken image.** This is automatic
(`src/components/destinations/DestinationImage.jsx`); there is nothing
to configure per destination.

## Replacing a placeholder with a real photo

Just overwrite the file — same name, same `.png` extension. No code
change needed anywhere; `destinationCatalogue.js` builds each card's
image path from the destination's own slug.

If you'd rather use `.jpg`/`.webp`, change the one line in
`destinationCatalogue.js` (`` image: `/images/destinations/${slug}.png` ``)
to the extension you're using, then use that extension for every file.

**Spec for the real photo, so it looks right in the card:**

- **Aspect ratio:** cards crop to 4:3 (`object-fit: cover`) — a
  landscape source photo with the main subject roughly centered (or
  in the upper half, for a tall subject like a temple tower) works best
- **File size:** a few hundred KB is plenty at the size these render at
- **Content:** a real photo of the place — landmark, view, or street
  scene that's recognizably that destination

If a particular photo's important subject sits off-center (a temple
gopuram's tip, a person in frame, a coastline that runs along one
edge), set `imagePosition` on that destination's entry in
`destinationCatalogue.js` — a CSS `object-position` value such as
`'top'` — rather than re-cropping the source file.

## Adding a new placeholder (e.g. a newly added destination)

```
node scripts/generate-placeholder-images.cjs <slug1> <slug2> ...
```

Writes a plain solid ice-blue placeholder for each slug given — safe
to run for a specific new destination, but don't run it for a slug
that already has a real photo, since it will overwrite that file.

`<slug>.png` (per the sections above) whenever you've confirmed which
destination they're for.
